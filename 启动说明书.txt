零、先看这一张表：你想做什么，就启动哪几个
================================================================================

这个项目不是一个程序，是「四个可以启动的东西」。它们互相独立，
不是每个都要开。

    你想看什么                  要启动什么                      大概耗时
    --------------------------  ------------------------------  ----------
    ① 网页版界面（最常用）      后端 + 前端（两个）              约 30 秒
    ② 桌面版窗口                桌面端（一个）                   约 5 秒
    ③ AI 能力演示               ai-service（一个）               约 3 秒
    ④ 全部都看                  后端 + 前端 + ai-service         约 40 秒

  · 数据库（MySQL）是 Windows 服务，开机自动运行。
    它不属于上面任何一个，也不需要你手动启动。

  · ② 和 ① 是两套界面，共用同一份业务逻辑，但**各跑各的**：
    看桌面版**不需要**启动后端和前端；看网页版也**不需要**启动桌面版。

  · 最省事的做法：**双击仓库根目录的 `start-dev.cmd`**，它会自动把 ① 起好，
    并等两个服务都就绪后帮你打开浏览器。详见第一章 A 节。


================================================================================
一、启动方式 A：网页版（最常用）
================================================================================

需要同时启动两个服务：后端（提供数据）+ 前端（提供页面）。
两个都必须开着，缺一个界面就用不了。


--------------------------------------------------------------------------------
A-1  最省事：双击 start-dev.cmd（推荐）
--------------------------------------------------------------------------------

  在文件资源管理器里进到 E:\二手房中介管理系统，**双击 start-dev.cmd**。

  它会依次做四件事：
    1. 检查 JAVA_HOME、检查前端依赖是否已装（没装会自动用国内镜像装）
    2. 弹出两个新窗口，分别启动后端和前端
    3. 等这两个服务都监听成功
    4. 自动用默认浏览器打开 http://localhost:5173

  · 它自己那个窗口跑完就可以关，**不影响已经启动的服务**。
  · **要保留的是它弹出的那两个新窗口** —— 关掉哪个，对应的服务就停了。


--------------------------------------------------------------------------------
A-2  手动方式：开两个 PowerShell 窗口
--------------------------------------------------------------------------------

  想自己控制、或者想看启动过程时用这个。

  【窗口 1 —— 后端】

      cd "E:\二手房中介管理系统"
      .\mvnw -pl realestate-web -am spring-boot:run

      ⚠️ `-am` 三个字符不能省。原因见第六章「常见问题」第 6 条。

  【窗口 2 —— 前端】

      cd "E:\二手房中介管理系统\frontend"
      npm run dev

      （依赖已经装好了，不需要再跑 npm install。
        万一将来要重装，加国内镜像快很多：
        npm install --registry=https://registry.npmmirror.com ）

  【然后】浏览器打开 http://localhost:5173

================================================================================
二、启动方式 B：桌面版窗口
================================================================================

桌面版是原来那个 Swing 程序，**自己直连数据库，不需要后端和前端**。

  【方式一：直接跑打好的 jar —— 最省事，不需要构建】

      cd "E:\二手房中介管理系统"
      java -jar realestate-desktop\target\realestate-desktop-1.0.0-SNAPSHOT-jar-with-dependencies.jar

      这个 jar 是自包含的（5.1 MB，里面已含全部依赖和 FlatLaf 界面库），
      所以拷到别的机器上也能直接跑。

  【方式二：用 Maven 跑源码】

      cd "E:\二手房中介管理系统"
      .\mvnw -q -DskipTests install          # 只需要先跑一次
      .\mvnw -pl realestate-desktop exec:java

      ⚠️ 第一条 `install` 不能跳过。`-pl realestate-desktop` 只把桌面端放进构建，
        它依赖的 realestate-core 只能从「本地 Maven 仓库」取，
        而仓库里那份可能已经过期。

  【怎么算成功】弹出一个登录窗口（左侧蓝色品牌区 + 右侧表单）。
                它不会打印什么明显的成功日志，窗口出来就是成功。


================================================================================
三、启动方式 C：AI 能力演示（ai-service）
================================================================================

先说清楚它是什么，免得误解：

  · 它**不是一个常驻服务**，不会监听端口、没有网页界面。
    它是一组 Python 脚本，**跑一次、看输出、结束**。
  · 它**独立于 Java 那部分**，不连你项目里的数据库，用的是自己的
    ai-service\data\houses.json（6 条示例房源）。
  · 所以：**不需要先启动后端或前端**，它自己就能跑。


--------------------------------------------------------------------------------
C-1  最快的一次验证：跑测试（不联网，不花额度）
--------------------------------------------------------------------------------

  cd "E:\二手房中介管理系统\ai-service"
  .venv\Scripts\python.exe -m pytest tests -q

  【怎么算成功】最后一行显示 `70 passed`。
  【实测】本机 2.03 秒跑完，70 项全部通过。

  > 这里直接调 `.venv\Scripts\python.exe`，**不用先「激活」虚拟环境**。
  > 为什么：PowerShell 里若写 `.venv\Scripts\activate`（不带 .bat），
  > 它会去加载 activate.ps1，而本机 PowerShell 执行策略是 Restricted，
  > 会报「因为在此系统上禁止运行脚本」。绕开最省事。


--------------------------------------------------------------------------------
C-2  离线跑完整链路：用本地假模型（不花额度，推荐先用这个看效果）
--------------------------------------------------------------------------------

  这个模式会真的起一个本地服务、真的收发 HTTP，只是模型回复是预设的。
  用来确认「除了模型答得好不好之外」的环节都通。

  【窗口 1 —— 假模型服务】

      cd "E:\二手房中介管理系统\ai-service"
      .venv\Scripts\python.exe tools\mock_llm_server.py 8899

      看到「假模型服务已启动：http://127.0.0.1:8899/v1」就是好了。

  【窗口 2 —— 跑演示】

      cd "E:\二手房中介管理系统\ai-service"

      $env:LLM_BASE_URL="http://127.0.0.1:8899/v1"
      $env:DASHSCOPE_API_KEY="sk-mock"
      .venv\Scripts\python.exe demo_day1.py

      （上面两行是 PowerShell 写法。如果你用的是 Git Bash，写成一行的形式：
        LLM_BASE_URL=http://127.0.0.1:8899/v1 DASHSCOPE_API_KEY=sk-mock .venv/Scripts/python.exe demo_day1.py ）

  【实测输出】首段到达 0.08s，全部完成 1.76s，共 55 段。


--------------------------------------------------------------------------------
C-3  真实调用大模型（要 API Key，会消耗额度）
--------------------------------------------------------------------------------

  前提：ai-service\.env 里的 DASHSCOPE_API_KEY 已填好真实密钥（已配好）。

      cd "E:\二手房中介管理系统\ai-service"

      .venv\Scripts\python.exe demo_day1.py            # 流式输出 + 结构化抽取
      .venv\Scripts\python.exe demo_day1.py --retry-demo   # 额外演示超时重试
      .venv\Scripts\python.exe demo_day2.py            # 本地房源检索问答
      .venv\Scripts\python.exe demo_day2.py "有没有带车位的房子？"

  · 网络：dashscope.aliyuncs.com 可直连，**不需要挂 VPN**。
  · 每次提问都会调用一次接口（一次向量化 + 一次对话），会产生少量费用。

  > 为什么 demo_day1 和 demo_day2 要分成两个文件：
  > day1 演示「自然语言 → 结构化字段」，day2 演示「语义检索」，
  > 两件事的依赖和数据都不同，混在一起不好讲也不好查错。

五、怎么关掉
================================================================================

  在各自的窗口里按 **Ctrl+C** —— 这是「请求正常停止」，最推荐。

  直接点窗口右上角的 × 也可以，一般不会有数据损坏风险。
  但偶尔会出现「× 掉了但进程没退干净」，下次启动就报
  「Port 8080 was already in use」。真遇到了按第六章第 5 条处理。

  【注意】**MySQL 不用关**，也不建议关 —— 它是独立服务，下次开机还要用。

六、常见问题
================================================================================

--------------------------------------------------------------------------------
（一）这些现象看着像坏了，其实都正常
--------------------------------------------------------------------------------

  1. 打开 http://localhost:8080 看到一段 JSON 报错
     正常。后端只回答数据、不回答页面（它没有网页）。
     想确认它活着，访问 http://localhost:8080/api/health 才对。

  2. 后端窗口在不停地打印日志
     正常。这是程序原有的调试输出（比如「尝试登录: admin」）。

  3. 浏览器打开 5173 之后，登录点了没反应
     多半是后端还没起来（后端比前端慢十几秒）。
     看一眼后端窗口有没有「Tomcat started on port 8080」，
     没有就再等等。双击 start-dev.cmd 启动的话不会遇到这个，
     因为脚本已经等两个服务都就绪才开浏览器。

  4. 改了前端代码保存后浏览器自动刷新，改了 Java 代码却没反应
     正常。前端有热更新（改 .vue 立即生效）；
     Java 改了必须重启后端窗口（Ctrl+C 后重新执行启动命令）。
     另：改了 vite.config.js 或后端 application.properties，
     也要重启对应服务 —— 配置文件不热更新。

  5. PowerShell 里 `git status` 显示 main...origin/main [gone]
     正常。E: 盘有个已知的环境缺陷，不影响 push/pull。忽略即可。


--------------------------------------------------------------------------------
（二）真的出错时怎么查
--------------------------------------------------------------------------------

  6. 后端报一堆「找不到符号」，或提示找不到某个类
     原因：`-pl` 只把选中的模块放进构建，它依赖的 realestate-core
           只能从本地 Maven 仓库取，而仓库里那份可能已经过期。
     解决：命令里加 `-am`（推荐，会按源码一起构建）：
              .\mvnw -pl realestate-web -am spring-boot:run
           或者先手动刷新一次本地仓库：
              .\mvnw -q -DskipTests install

  7. 后端报「Port 8080 was already in use」
     原因：上一次的进程没退干净。
     解决：在 PowerShell 里执行下面这行（会杀掉占用 8080 的进程）：
              Get-NetTCPConnection -LocalPort 8080 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
           把 8080 换成 5173 可以处理前端同样的问题。

  8. 后端报「无法连接数据库」/ 连接被拒绝
     检查：MySQL 服务在不在跑。Win+R 输入 services.msc，
           找 MySQL80 看状态是不是「正在运行」。

  9. PowerShell 里 npm 报「因为在此系统上禁止运行脚本」
     原因：PowerShell 的 npm 入口是 npm.ps1，受执行策略管。
     已解决过（2026-09-19 把 CurrentUser 策略设为 RemoteSigned）。
     如果又出现，两个办法：
       · 改用 npm.cmd 代替 npm，例如：npm.cmd run dev
       · 或重新执行一次：Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
     注意：**这个改动只对之后新开的窗口生效**，改完要重开窗口。

 10. ai-service 报「缺少 DASHSCOPE_API_KEY」
     检查 ai-service\.env 文件里那一行有没有填真实密钥。
     申请地址：https://bailian.console.aliyun.com/ → 右上角「API-KEY」。
     代码里刻意不留内置默认密钥 —— 缺了会直接报错，而不是带着空 Key 发请求。

八、登录账号
================================================================================

  有两个角色：

      admin    管理员   —— 可以删除房屋 / 客户 / 带看记录
      agent    经纪人   —— 能看、能加、能改，但删除按钮是灰的

  口令不写在这份文档里 —— 源码与文档里出现明文口令是坏习惯，
  而且这个仓库是公开的。

  需要时这样找：源码里搜 `encryptPassword`，它的参数就是初始口令，
  位置在 realestate-core/src/main/java/dao/DatabaseUtil.java 的
  initializeDatabase() 方法里。

  两个账号都是首次建库时写入的（INSERT IGNORE，只在不存在时创建）。
  所以：**改了源码里的预设口令，不会更新库里已有的记录。**
  要改口令，用界面右上角的「修改密码」功能。
